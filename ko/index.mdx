Lynx는 하나의 사용자 요청이 LLM 호출, 도구 호출, 정책 판단, 재시도, 최종 결과로 이어지는 과정을 기록합니다. TypeScript SDK를 사용하거나 어떤 실행 환경이든 HTTP로 연결할 수 있습니다.

<Warning>
  Lynx는 현재 파일럿 단계의 프로젝트이며, 정식 출시 전까지 API와 동작이 변경될
  수 있습니다. 파일럿 참여 또는 서비스 도입 테스트를 원하면
  [partners@hvnn.me](mailto:partners@hvnn.me)로 연락해 주세요.
</Warning>

## 연결 방식 선택

비동기 실행 컨텍스트, LLM과 도구 감싸기, 로컬 방화벽, 배치 전송, 재시도, 런타임 설정 저장이 필요하면 TypeScript SDK를 사용하세요.

다음 경우에는 OpenAPI를 직접 사용할 수 있습니다.

- 서비스가 다른 언어나 실행 환경을 사용합니다.
- 공개용 또는 사내용 SDK를 새로 만듭니다.
- 이미 이벤트 큐와 전송 시스템을 운영하고 있습니다.
- 로컬 저장 방식과 정책 실행을 직접 제어해야 합니다.

두 연결 방식은 같은 Run, Session, Event, 프롬프트 버전, 정책, 이슈 기록 모델을 사용합니다.

## 핵심 흐름

```text
이벤트 기록
→ Run 타임라인 복원
→ 원인 후보와 근거 확인
→ 위험한 도구 호출을 로컬에서 차단
→ 이슈 후보 접수
→ 프롬프트와 정책 개선
```

Lynx에서는 입력, 실행 단계, LLM 호출, 도구 호출, 오류, 재시도, 지연 시간, 토큰, 비용, 정책 판단, 관련 프롬프트 버전을 하나의 Run에서 확인할 수 있습니다.

## 운영 환경 안전성

일반 이벤트는 백그라운드에서 전송해야 합니다. Lynx API에 일시적으로 접근할 수 없어도 고객 요청이 실패하면 안 됩니다. 크기가 제한된 큐, 짧은 timeout, 선택적 재시도, 서킷 브레이커를 사용하세요.

방화벽은 도구 실행 직전에 로컬에서 판단합니다. 고위험 동작은 네트워크 호출에 의존하지 않고 차단하거나 승인을 요구할 수 있습니다.

<Note>
  프롬프트, 도구 인자, 모델 응답, 로그, payload에는 민감정보가 들어갈 수
  있습니다. 기록하기 전에 비밀값을 마스킹하고, 원문이 필요하지 않으면
  `metadata-only` 수집 모드를 사용하세요.
</Note>
